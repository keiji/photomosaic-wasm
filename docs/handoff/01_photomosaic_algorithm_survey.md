# ハンドオフ資料 1: フォトモザイク処理の一般的な実装方法(調査まとめ)

| 項目 | 内容 |
|---|---|
| 性格 | 本アプリに限定しない、世の中で提供されているフォトモザイク処理手法の調査整理 |
| 用途 | 実装方式の選定根拠、将来のアルゴリズム改善検討の足場 |

## 1. フォトモザイクの基本構造

フォトモザイク(Photo Mosaic)は、ベース画像を格子状のセルに分割し、各セルを色や質感が近い小さな画像(タイル)で置き換えることで、近くで見ると小さな写真の集まり、遠くから見ると 1 枚の絵に見える表現である。商標としての "Photomosaic" は Robert Silvers らの手法(1990 年代後半)に由来するが、本資料では技術一般を指す語として用いる。

処理はすべて次の 2 段構造に集約できる。

1. **特徴量化**: ベース画像の各セルとタイル候補群を、比較可能な数値(特徴量)にする
2. **割り当て**: 各セルに対し「最適な」タイルを選んで配置する

実装の違いはこの 2 段階、特に「何を特徴量にするか」「どう割り当てるか」に現れる。

## 2. 特徴量の種類と比較

| 特徴量 | 計算コスト | 見た目の品質 | 実装難度 | 備考 |
|---|---|---|---|---|
| 平均 RGB | 極小 | 低〜中 | 極小 | 最も単純。sRGB のまま平均すると暗部・明部の混色が不自然になりやすい |
| 平均色の知覚色空間表現(Lab / LabHV) | 小 | 中 | 小 | 色距離 ΔE で人間の感覚に近い比較ができる。定番 |
| カラーヒストグラム | 中 | 中 | 中 | 色の分布を見る。単一の代表色にしづらいタイルで効く |
| 明度ヒストグラム / 勾配 | 中 | 中〜高 | 中 | タイルの「明暗の模様」まで考慮できる |
| ディテール量(分散・エッジ量) | 小 | 中 | 小 | 色だけでは表現できない「細かさ」を数値化。色マッチの補助に有効 |
| 感覚的ハッシュ (pHash / dHash) | 中 | 中 | 中 | 類似画像検索に近い発想。明暗構造の類似を評価 |
| 局所特徴量 / CNN 埋め込み | 大 | 高(意味論的) | 大 | 「犬の写真を犬のタイルで」という配置が可能になる。重く、オフライン端末では不利 |

実務の多くのツールは「**平均色(知覚色空間)+ ディテール量**」の組み合わせを基本とし、必要に応じてヒストグラム等を足している。CNN 埋め込みを使う研究・ツールも存在するが、モデル配布サイズと計算コストの観点からモバイル完全オフライン用途では採用しづらい。

## 3. 割り当て(マッチング)方式の系統

### 3.1 独立貪欲マッチング(グリーディ)

各セルを独立に「距離最小のタイル」へ割り当てる方式。最も一般的で、AndreaMosaic や MacOSaiX など定番ツールの基本動作、OSS の python `photomosaic` ライブラリ、Metapixel や Pixelize など CLI ツールもこの系統(オプションで重み付けの多様な調整が可能)。

- 長所: 高速(O(N×M))、実装が容易、ストリーミング表示(割当済みセルから順に見せる)と相性が良い
- 短所: 全体として同じタイルが偏在しやすい(同じ空模様のセルに同じタイルが集中)
- 対策: 使用回数ペナルティ、使用回数上限、隣接セルとの同一配置ペナルティ(後述 5 章)

### 3.2 大域最適化

セルとタイルの割り当てを「全体の距離の総和 + 多様性制約」の最小化問題として解く方式。研究分野では Di Blasi & Gallo の人工モザイク手法(エネルギー最小化)などが知られる。割り当て問題としてハンガリアン法・最小費用流などで厳密解を狙う場合と、分割統治・確率的近似(焼きなまし等)で実用的時間に収める場合がある。

- 長所: タイルの偏りがなく、芸術的な完成度が高い
- 短所: 計算量が桁違いに大きく(数十万セルでは非現実的)、進捗の段階的表示が難しい
- 用途: 高品質出力のデスクトップツール。インタラクティブなプレビューには不向き

### 3.3 階層・距離適応型

「遠目で全体像・近目でタイルのディテール」という 2 つの見え方を制御する発想。セルごとにベース画像の残像をタイルにブレンドする(後述 6 章の色補正)、または複数のタイル解像度を使い分ける方式。プレビュー表示の UX と直結し、実用ツールで広く使われる。

### 3.4 検索型(データベース型)

タイル群をデータベース化し、k-d 木・VP 木・LSH・HNSW などの近傍探索インデックスで候補を引く方式。タイル数千〜数万枚を扱うツールで採用される。特徴量次元が低い(Lab+ディテールの 4 次元程度)場合は k-d 木が有効。

## 4. 距離(類似度)の計算

| 指標 | 説明 |
|---|---|
| ΔE76 (CIELAB のユークリッド距離) | 最も広く使われる。計算が軽く、実用上十分な精度 |
| ΔE94 / ΔE2000 | より知覚的に正確だが計算は重い。タイル候補が近接する場合の仕上がり差は小さい |
| ヒストグラム交差 / EMD | 色分布の一致度。コストが高く、主に高品質ツール向け |

本アプリのように「平均色 + ディテール」でマッチする場合、ΔE76 ベースで十分とされる(詳細設計書の距離関数を参照)。

## 5. タイル再利用の制御

| 方式 | 挙動 | 向き |
|---|---|---|
| 無制限再利用 | 同じタイルが何度でも使われる。平均色が似た領域は同一タイルだらけになる | タイル数が極端に少ない場合のみ |
| 使用回数上限 (cap) | 1 タイルの使用を N 回までに制限。全タイルが上限に達したらリセット | 定番。タイル数がセル数より少ない場合に必須 |
| 使用回数ペナルティ | 使うほど選ばれにくくなる。自然な分散を生む | cap と併用が一般的 |
| 完全一意(1 回のみ) | 各タイルを最大 1 回使用 | タイル数 ≥ セル数の特別な作品向け |
| 隣接制約 | 直上・直左と同じタイルを避ける/ペナルティ | 縞模様の目立ちを防ぐ |

## 6. 色補正(タイルをセルの色へ寄せる処理)

セルの平均色とタイルの平均色の差を、タイル描画時に補正することで、遠目の全体像を強く出す手法。実装系統は次の通り。

| 方式 | 内容 | 特徴 |
|---|---|---|
| なし | タイル原色のパッチワーク | 全体像が見えにくい。素材の魅力は最大 |
| 乗算 (multiply) | タイル色 × セル平均色/タイル平均色 | 明部・暗部が崩れにくく定番。本アプリ採用(詳細設計書 4.6) |
| オーバーレイ / ソフトライト | セルの明度をタイルへ重ねる | コントラストが残り、アート寄り |
| ヒストグラムマッチング | タイルの明度分布をセル分布へ整合 | 高品質だが重い |

補正強度をパラメータ化(0〜1)するのが実用上の定石で、強度 0 を「素材重視」、1 を「全体像重視」としてユーザーに選ばせるツールも多い。

## 7. 性能上の工夫(世間の実装から)

- タイルのサムネイル化・特徴量の事前計算・キャッシュ(本アプリも採用)
- 近傍探索インデックス(k-d 木など)による候補絞り込み(タイル大量時)
- SIMD / マルチスレッド / GPU(デスクトップツール)。モバイル完全オフラインではマルチスレッドは WASM Threads の制約(COOP/COEP ヘッダ)があるため避けて設計
- セル単位のバッチ処理と進捗通知(UI の応答性確保)

## 8. 代表的な既存ツール・ライブラリ

| 名称 | 形態 | 特徴 |
|---|---|---|
| AndreaMosaic | Windows フリーウェア | 定番デスクトップツール。タイル重み付け、色補正、セルサイズ調整など実用機能が網羅的 |
| MacOSaiX | macOS フリーウェア | iPhoto ライブラリ等と連携。複数のマッチング戦略を選択可能 |
| Metapixel | Linux CLI | グリッド/コラージュ両モード。タイル重複抑制や近傍探索を実装 |
| Pixelize | Linux GUI | 平均色ベースのシンプルな実装 |
| python `photomosaic` | Python ライブラリ | Lab 色空間 + 近傍探索。アルゴリズム学習用の参考実装として読みやすい |
| ImageMagick (`montage`) | CLI | フォトモザイク専用ではないが、単純タイル貼り合わせの検証に使える |

## 9. 本アプリ設計への反映(採用方針)

| 項目 | 採用 | 理由 |
|---|---|---|
| 特徴量 | 平均色(CIELAB)+ ディテール量(L* 標準偏差) | 軽量でオフライン端末に適し、品質と速度のバランスが良い |
| マッチング | 独立貪欲 + 使用ペナルティ + 使用上限 + 隣接ペナルティ | ストリーミング表示(進捗バー・段階的置き換え)と相性が最良。大域最適化は速度面で不採用 |
| 近傍探索 | タイル 2,000 枚以下は総当たり、超えたら k-d 木 | 実測に基づく切り替え(性能計測設計で検証) |
| 色補正 | 乗算方式、強度 α を設定可能 | 遠目の視認性とタイルの質感の両立 |
| 平均色計算 | 線形ライトで平均 → Lab 変換 | sRGB 平均の混色不自然さを回避 |
| ΔE | ΔE76 | 計算コストと知覚精度のバランス |

将来的な拡張候補(スコープ外、設計に影響しない形で差し替え可能なようにコアは特徴量・距離関数をモジュール化):
- 勾配指向の一致(模様の向きを揃える)
- 明度ヒストグラム距離の追加
- 学習済み埋め込みを用いた意味論的マッチング(モデルを端末同梱する場合)
