| 項目 | 内容 |
|---|---|

## 1. 目的

ユーザーが持ち込んだ 1 枚の画像(メイン画像)を小さなブロックに分割し、各ブロックの色合い・輝度にマッチする複数の小画像(構成画像)を配置することで、フォトモザイク(モザイクアート)画像を生成するアプリケーション群を提供する。

フォトモザイクの合成処理は WebAssembly (WASM) による共通コアとして実装し、Web アプリと Android アプリから同じアルゴリズム・同じ挙動・同じ進捗インターフェースで利用できるようにする。

## 2. プロダクト構成

本プロジェクトは次の 3 要素からなる。

| 要素 | 技術 | 役割 |
|---|---|---|
| 共通コア (photomosaic core) | Rust (WASM にコンパイル) | フォトモザイク合成の全処理。ブロック分割、特徴量解析、タイル選択、合成、進捗通知 |
| Web アプリ | TypeScript + JavaScript (Vite) | スマートフォン対応のブラウザアプリ。WASM コアを呼び出して UI を提供 |
| Android アプリ | Kotlin + Jetpack Compose | ネイティブ Android アプリ。Web と同一の WASM コアを JavaScript エンジン(androidx.javascriptengine)上で実行して UI を提供 |

※ Android も Web と同じ .wasm を実行する。Android SDK には WASM ランタイムが標準搭載されていないため、AndroidX の JavaScript Engine(androidx.javascriptengine: `JavaScriptSandbox` / `JavaScriptIsolate`)を処理ホストとして使用し、ホストとの双方向通信は **MessagePort API** を使用する。JNI 経由でネイティブコードを動かす方式(自作 cdylib の JNI バインディング等)はセキュリティリスクの観点から採用しない。詳細は [詳細設計書](./03_detailed_design.md)、[Android 実装手順](./handoff/06_android_implementation_guide.md) および [Go/Rust 選定資料](./handoff/03_go_vs_rust.md) を参照。

## 3. 主要機能

1. **メイン画像の設定**
   - Web: ファイル選択またはドラッグ & ドロップ。設定すると画面にプレビュー表示する。
   - Android: ボタンからメディアピッカー(Photo Picker)を起動して選択。

2. **ブロックサイズの設定**
   - シークバー(スライダー)でブロックの 1 辺の大きさを指定する。
   - 変更するたびにブロック数が確定し、プレビューのグリッド表示とフォトモザイクの再生成が行われる。

3. **構成画像(タイル)の設定**
   - Web: 複数ファイルのドラッグ & ドロップまたはファイル選択。
   - Android: ボタンからメディアピッカーを起動して複数選択。
   - 追加されたタイルは解析されてプールに登録され、メイン画像の各ブロックに適切なものが割り当てられる。

4. **フォトモザイクの生成と段階的表示**
   - メイン画像をブロックに分割し、各ブロックの平均色・輝度・ディテールを算出する。
   - 構成画像も縮小した上で平均色・輝度・ディテールを解析し、ブロックにマッチするものを選択・配置する。
   - メイン画像がフォトモザイクへ段階的に置き換わっていく様子をプレビューに反映する。

5. **進捗の可視化**
   - フェーズ単位の進捗と、フェーズ内の進捗をコールバックで取得できる。
   - メイン画像読み込み後に全体ブロック数が確定し、「割り当て済みブロック数 / 全体ブロック数」を横方向の進捗バーで表示する。

6. **保存**
   - Web: 完成したフォトモザイク画像をブラウザ経由でダウンロードする。
   - Android: メディア画像として端末に保存し、そのまま共有アクションを呼び出せる。

## 4. 完全オフラインとプライバシー

本プロダクトは **完全オフライン** で動作する。

- サーバーや外部サービスと一切通信しない(アップロードも解析もない)。
- メイン画像・構成画像に顔写真が含まれていても、データが端末の外に出る経路が存在しない。
- Android アプリは `INTERNET` パーミッションを要求しない。
- Android の JavaScript エンジンはアプリとは別プロセスのサンドボックス(`JavaScriptSandbox`)上で動き、ネットワークもファイルシステムも直接扱えない。ローカルのアセットから読み込んだコードのみを実行する(多層防御)。
- Web アプリは GitHub Pages で公開する。初回アクセス時の静的アセット取得後はネットワーク断でも動作する(Service Worker によるキャッシュ。HTTPS は GitHub Pages が満たす)。
- テレメトリ・クラッシュレポート・広告などの通信機能は実装しない。
- 保存したフォトモザイク画像には入力画像のメタデータ(EXIF の撮影位置等)を引き継がない(ピクセルからの再エンコードにより取り除く)。

これにより、顔写真など機微性の高い画像を含むユーザーでも、**プライバシーリスクが極めて低い** 状態でフォトモザイク生成を利用できる。この点を本プロダクトの最重要の価値の一つと位置づける。

## 5. 想定利用者とユースケース

| 利用者 | ユースケース |
|---|---|
| 一般ユーザー | 旅や家族の思い出の写真を、集めた小さな写真群で作り上げたフォトモザイクにして飾る・共有する |
| 写真好き・創作者 | 大量の自分の作品群をタイルとして、代表作をフォトモザイク化する |
| プライバシー重視のユーザー | 顔写真を外部送信したくないが、個人的な記念物としてフォトモザイクを作りたい |

## 6. スコープ

### スコープ内
- Web アプリ(TypeScript)、Android アプリ(Kotlin + Compose)、共通コア(Rust → WASM。Web と Android で同一の .wasm を実行)
- フォトモザイク生成エンジンと進捗通知インターフェース
- 画像の保存(ダウンロード / メディア保存)と共有(Android)
- 性能計測の仕組み(処理フェーズごとの所要時間)
- ソースコードの公開(MIT ライセンス)

### スコープ外
- サーバー側処理、アカウント管理、同期機能
- クラウドストレージ連携、SNS 直接投稿機能(共有は OS 標準の共有機能に委ねる)
- 動画フォトモザイク、既製のタイル素材集の同梱配布(ユーザー持ち込みのみ)
- AI/機械学習によるタイル推薦

## 7. 技術スタック一覧

| レイヤー | Web | Android | 共通コア |
|---|---|---|---|
| 言語 | TypeScript | Kotlin | Rust |
| UI | 標準 DOM + Canvas | Jetpack Compose | - |
| 実行形態 | WebAssembly (wasm32-unknown-unknown) | JavaScript Engine(androidx.javascriptengine)上で Web と同一の .wasm を実行 | 同左(Android は JS サンドボックス ホスト) |
| 画像デコード | ブラウザ標準 (`createImageBitmap` / `<canvas>`) | Kotlin (`ImageDecoder` / `BitmapFactory`) | コアではデコードしない(ホスト側の責務) |
| 保存 | `canvas.toBlob` + download | MediaStore + 共有インテント | エンコード前の RGBA バッファを返却 |

## 8. 品質目標

| 項目 | 目標 |
|---|---|
| オフライン動作 | 全機能が通信なしで動作すること(通信コードは存在しない) |
| 性能 | 代表条件(メイン 12MP・タイル 300 枚・ブロック 24px)で生成完了までおおむね 3 秒以内(ミッドレンジのデスクトップ相当)。詳細は[性能計測設計](./handoff/05_performance_measurement.md) |
| プラットフォーム間の一貫性 | Web と Android は同一のコア・同一の .wasm で動作する(ホストは JS 環境で共通)。同一入力ピクセルに対するコア出力は決定的 |
| 進捗の見やすさ | 全体ブロック数はメイン画像設定直後に判明し、進捗バーは常時反応する(16ms 以上フリーズしない) |

## 9. 用語定義

| 用語 | 意味 |
|---|---|
| メイン画像 | フォトモザイクの元になる画像。ブロックに分割される。 |
| 構成画像(タイル) | ブロックに配置される小さな画像。ユーザーが複数枚持ち込む。 |
| ブロック | メイン画像を格子状に分割した矩形セル。1 ブロックに 1 枚のタイルが割り当てられる。 |
| タイルプール | 解析済み構成画像の集合。ブロックへの割り当て候補。 |
| 特徴量 | ブロックやタイルから抽出する解析結果(平均色・輝度・ディテール等)。 |
| マッチング | 各ブロックに最適なタイルを選ぶ処理。 |
| 合成 (コンポーズ) | 選ばれたタイルをブロックへ描画し最終画像を作る処理。 |
| フェーズ | 処理の大区分(読み込み・解析・マッチング・合成など)。 |
| コア | Web と Android で共有するフォトモザイク処理本体(Rust 実装)。 |
